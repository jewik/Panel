# Panel — исследование: какие функции добавить

> **Дата:** 30 октября 2026.
> **Метод:** веб-исследование конкурентов и публичных API macOS (агент explore), затем выборочная проверка ключевых утверждений.
> **Деплоймент-таргет проекта:** macOS 15+. API, появившиеся в macOS 26 и позже, помечены в тексте явно — перед реализацией сверяйте доступность по актуальному SDK.
>
> **Статус проверки.** Подтверждено существование: Foundation Models, ScreenCaptureKit `SCScreenshotManager`, Core Audio `CATapDescription`, `SMAppService`, EventKit full-access APIs, `ProcessInfo.beginActivity`. **Требует проверки перед реализацией:** история буфера в Spotlight (⌘4) и `NSPasteboard.accessBehavior` (упомянутый URL документации отдаёт 404 — возможно, API называется иначе или появился в другой версии ОС); точные сроки/версии релизов macOS 26/27. Веб-поиск на момент подготовки файла результатов не давал, поэтому ссылки в §8 — из выдачи агента, их стоит открыть вручную.
>
> **Как читать:** S/M/L — сложность (Small / Medium / Large); «impact» — ожидаемое влияние на удержание и дифференциацию. Все идеи предполагают расширение `PanelPreset` и навигационного ряда, а не переделку каркаса панели.

## 1. Резюме

1. **Форм-фактор «снизу» — это не «нотч-приложение», а отдельный класс.** Все конкуренты (NotchNook, DynamicLake, Boring Notch, Alcove, NotchDrop) сидят **сверху**, у нотча, и конкурируют за одно и то же место. Нижняя панель ближе к Dock, к рукам и к перетаскиванию «вниз» — это другая ниша, и копировать нотч-фичи 1:1 нельзя, нужно брать только те, что выигрывают от близости к нижнему краю.
2. **Главный незанятый сценарий — «drop-to-action».** Полка есть у всех (NotchDrop, Dropover, Yoink, Boring Notch, NotchNook Tray), но почти все только *держат* файлы. Панель, которая **сразу делает** с брошенным файлом действие (OCR, конвертация, сжатие, отправка в папку, AI-переименование) — сильная дифференциация.
3. **macOS 26 обесценила часть фич.** Spotlight получил историю буфера обмена (⌘4) и действия — строить clipboard-менеджер как основную фичу теперь поздно. Одновременно macOS 26 добавила запрос разрешения на чтение пастборда — это ещё и риск. *(утверждение требует проверки, см. блок выше)*
4. **Media/Now Playing — ловушка.** Публичного API чтения чужого Now Playing нет; `MPNowPlayingInfoCenter` только публикует своё. MediaRemote — приватный фреймворк, с macOS 15.4 прямой вызов сломан, обходится запуском `/usr/bin/perl` (bundle id `com.apple.*`). Это не фундамент для продукта.
5. **Публичные и «дешёвые» источники ценности:** EventKit (календарь), Vision OCR, Core Audio taps (per-app звук), `host_statistics64`/IOPS (метрики), FSEvents/`NSMetadataQuery` (инбокс файлов), `ProcessInfo.beginActivity` (keep awake), FoundationModels (on-device AI, 26+).
6. **Лучшие 4 первых фичи:** (1) Полка с действиями, (2) «Дальше» — встреча + join, (3) AI-drop (суммаризация/OCR/переименование on-device), (4) Инбокс новых файлов (Downloads/Desktop). Пятая — Keep Awake + мини-виталка, как «дешёвый» бонус к удержанию.
7. **Разрешения — главный источник трения и оттока.** Календарь и камера/микрофон дают системный prompt, Accessibility и Screen Recording — «тихие» (пользователь должен сам включить в System Settings и перезапустить приложение), Full Disk Access не запрашивается программно вообще.
8. **Энергия и multi-display — два технических риска №1.** Панель на встроенном дисплее исчезает в clamshell-режиме; таймеры 1 Гц и постоянный ScreenCapture — главные причины, почему нотч-утилиты ругают за батарею.

## 2. Продукт и форм-фактор (кратко, что диктует панель)

| Свойство панели | Что из этого следует |
|---|---|
| Accessory app, без иконки в Dock | Нет «главного окна» → все настройки и контент должны жить в панели и в menu-bar-иконке. Уведомления `UNUserNotificationCenter` работают, но требуют корректного bundle id и подписи. |
| Низ экрана, 1000×400 pt, hover-раскрытие | «Зона большого пальца» и трекпада; конфликт с Dock (auto-hide) → позиционировать по `NSScreen.visibleFrame`, а не `frame`. |
| Свёрнута по умолчанию | Свёрнутое состояние — **это и есть продукт**: 1–3 чипа с самой горячей информацией (следующая встреча, таймер, счётчик новых файлов). |
| Drag & drop как основной вход | Любая фича должна иметь «drop-версию»: бросил файл/текст/картинку — получил результат. Это дешевле, чем учить пользователя хоткеям. |
| Навигация + пресеты (`.home`, `.fastfolder`, `.airdrop`, `.settings`) | Новые фичи = новые пресеты (`.shelf`, `.now`, `.inbox`, `.ai`) + чипы в свёрнутом состоянии; ломать существующую модель не нужно. |
| Anchored к встроенному дисплею | Нужен fallback: clamshell / внешний монитор / зеркалирование / Stage Manager. |
| Уже есть FastFolder (8 папок, security-scoped bookmarks, теги Finder) | Полка и инбокс должны **переиспользовать** bookmark-инфраструктуру и теги, а не заводить вторую файловую модель. |

## 4. Идеи функций

### 4.1 Быстрые победы

#### 4.1.1 Полка с действиями (Drop Actions Shelf) — S/M, impact: высокий
- **Питч/проблема:** пользователь тащит файл и «некуда бросить»; полки держат файл, но не помогают с ним ничего сделать. Нужна полка, которая сразу предлагает 3–5 осмысленных действий по типу файла.
- **В панели:** collapsed — чип «Полка: 3»; hover/expand — горизонтальная лента превью (иконка/thumbnail, имя, размер, тег Finder); drag-over — панель раскрывается и подсвечивает зону; drop — файл добавляется и появляется ряд действий; drag-out — `NSFilePromiseProvider`, чтобы работало перетаскивание в любые приложения.
- **Действия (v1):** AirDrop/Share, «Переместить в FastFolder» (из существующих 8 папок), «Сжать в ZIP» (`NSFileCoordinator` + `ditto`/`Archive`), «Конвертировать изображение» (ImageIO: HEIC→JPEG/PNG, resize), «Копировать путь», «Показать в Finder», «В корзину» (`FileManager.trashItem`), «Быстрый просмотр» (Quick Look).
- **API и разрешения:** `NSFilePromiseProvider`, `NSItemProvider`, `QLThumbnailGenerator` (QuickLookThumbnailing, без разрешений), `FileManager.trashItem(at:resultingItemURL:)` [30], security-scoped bookmarks (уже есть). Разрешений не требуется, если файлы пришли drag&drop или из bookmark.
- **Sandbox/App Store:** полностью совместимо. В песочнице нужен `com.apple.security.files.bookmarks.app-scope` для сохранённых папок и `user-selected.read-write` для drop.
- **Архитектура:** `ShelfService` (protocol) + `ShelfStore` (`@Observable`, `items: [ShelfItem]`, `state: ShelfState`), `ShelfViewModel` (`@MainActor`, typed events `ShelfEvent.dropped([URL]) / .actionFinished(ActionID)`), `ShelfPresetView` + `ShelfItemView`. Действия — отдельные `ShelfAction`-протоколы (Command pattern), чтобы не раздувать ViewModel.
- **Риски зависаний (как network volume):** `URL.resourceValues(forKeys:)` и `contentsOfDirectory` на сетевых/iCloud-томах блокируются — только на фоновом акторе, с таймаутом и `Task.checkCancellation()`; размеры папок не считать синхронно; thumbnail для видео/PDF — с лимитом и кэшем.
- **Сложность/риск:** S–M / низкий (только файловые права).
- **Конкуренты/дифференциатор:** NotchDrop, Dropover, Yoink, DropNotch — все «держат». Дифференциатор: **связка с FastFolder** (переместить в одну из 8 избранных папок одним броском) и действия по типу файла. [4][5][11][13][14]
- **Источники:** [4][5][11][13][14][30].

#### 4.1.2 OCR-приёмник (drop image/PDF → текст) — S, impact: высокий
- **Питч/проблема:** нужно вытащить текст из скриншота, PDF-страницы, фото доски. Сейчас — Preview/онлайн-сервисы.
- **В панели:** collapsed — ничего (фича «по требованию»); expanded — зона «Брось картинку или PDF»; drop → прогресс → карточка с распознанным текстом, кнопки «Скопировать», «В заметку», «В буфер и закрыть». Hover по результату — превью источника.
- **API и разрешения:** Vision `RecognizeTextRequest` (macOS 15+) или `VNRecognizeTextRequest` (10.15+), on-device, без разрешений [31]; PDF — `PDFKit`/`CGPDFDocument` для рендера страницы.
- **Sandbox/App Store:** совместимо, сеть не нужна (важный аргумент приватности).
- **Архитектура:** `OCRService` (protocol, `func recognize(_ url: URL) async throws -> OCRResult`), `OCRViewModel` со `state: .idle/.processing(progress)/.result/.failed`, View `OCRResultCard`. Всё на фоне (`Task.detached`/actor), UI только по `@MainActor`.
- **Риски:** большие PDF (сотни страниц) — ограничить первые N страниц и показывать «обработать все»; тяжёлые изображения — downscale до 2–3k px.
- **Сложность/риск:** S / низкий.
- **Конкуренты/дифференциатор:** Dropover умеет извлекать текст; NotchNook/DynamicLake — нет акцента. Дифференциатор: **бесплатно, офлайн, из свёрнутой панели за один бросок**. [13]
- **Источники:** [13][31].

#### 4.1.3 «Дальше»: следующая встреча + Join — S/M, impact: высокий
- **Питч/проблема:** люди не помнят, что через 5 минут созвон; открывать календарь ради этого дорого.
- **В панели:** collapsed — чип «Через 12 мин · Дизайн-ревью» (обновляется раз в минуту); expanded — «сейчас / следующие 3 события», кнопка Join, если в `EKEvent.url` или notes есть ссылка; hover — участники/место.
- **API и разрешения:** EventKit `EKEventStore`, `requestFullAccessToEvents()` (macOS 14+) [32]; Info.plist `NSCalendarsFullAccessUsageDescription` (и `NSCalendarsWriteOnlyAccessUsageDescription`, если создаём события); в песочнице — `com.apple.security.personal-information.calendars`. Ссылки ищем `NSDataDetector`/regex по `event.url`, `location`, `notes` (Meet/Zoom/Teams/Webex).
- **Sandbox/App Store:** совместимо; App Review любит, когда есть понятное объяснение usage string.
- **Архитектура:** `CalendarService` (protocol) + `CalendarStore` (`@Observable`, `events: [EventSummary]`, `authorization: .notDetermined/.granted/.denied`), `NextUpViewModel`, `NextUpPresetView` + `NextUpChipView` для collapsed. Обновление — по `EKEventStoreChanged` + таймер на границе минут (coalesced).
- **Риски зависаний:** `events(matching:)` на большом календаре/сетевом Exchange-аккаунте может быть медленным → только фон, диапазон ±7 дней, без синхронных вызовов из View.
- **Сложность/риск:** S–M / средний (permission denial → нужен аккуратный empty-state).
- **Конкуренты/дифференциатор:** NotchNook (join-кнопки), Dato, MeetingBar, Itsycal, DynamicLake. Дифференциатор: **countdown внизу + Join + «бросить файл к встрече»** (attachments к следующему событию). [1][25][26][27]
- **Источники:** [1][25][26][27][32].

#### 4.1.4 Keep Awake / таймер фокуса — S, impact: средний
- **Питч/проблема:** «не дай Mac уснуть на 30 минут» — частая задача; Amphetamine мощный, но живёт в меню-баре и требует настройки.
- **В панели:** collapsed — чип «☕︎ 23:41»; expanded — пресеты 5/15/30/60 мин, «до конца задачи»; drag&drop не нужен; hover — «почему не спит» (что именно удерживается).
- **API и разрешения:** `ProcessInfo.processInfo.beginActivity(options: [.idleSystemSleepDisabled, .userInitiated], reason:)` + `endActivity` [33]. Разрешений нет. Опционально `IOPMAssertionCreateWithName` (IOKit) — но Foundation-путь проще и достаточен.
- **Sandbox/App Store:** совместимо.
- **Архитектура:** `KeepAwakeService` (protocol, `start(duration:)`, `stop()`, `remaining: AsyncStream<Duration>`), `KeepAwakeViewModel`, чип + `KeepAwakePresetView`. Важно: гарантированно `endActivity` на `willSleep`/terminate, иначе «утечка» assertion.
- **Риски:** закрытая крышка (clamshell) — отдельная история, требующая других механизмов; не обещать «работает с закрытой крышкой». Энергия: таймер раз в секунду только при активном чипе, иначе — раз в минуту.
- **Сложность/риск:** S / низкий.
- **Конкуренты/дифференциатор:** Amphetamine, NotchDrop (Keep Awake). Дифференциатор: один клик из нижней панели + понятный статус. [23][5]
- **Источники:** [23][5][33].

#### 4.1.5 Мини-виталка (CPU/RAM/сеть/диск/батарея) — M, impact: средний
- **Питч/проблема:** «почему вентилятор?», «что жрёт RAM?», «какой IP?» — быстрый glance без открытия Activity Monitor.
- **В панели:** collapsed — 3 мини-спарклайна (CPU, RAM, сеть) или один выбранный; expanded — карточки с историей 60 сек, топ-3 процесса по CPU/RAM, текущий SSID/IP; hover — детали.
- **API и разрешения:** `host_statistics64` (vm_statistics64) и `host_processor_info` (mach) для CPU/RAM; `getifaddrs` для байтов по интерфейсам; `URLResourceValues`/`statfs` для диска; `IOPSCopyPowerSourcesInfo`/`IOPSGetPowerSourceDescription` для батареи; `ProcessInfo.thermalState`, `isLowPowerModeEnabled`. Разрешений нет. **Не** использовать SMC/`powermetrics` (см. §6).
- **Sandbox/App Store:** совместимо; `sysctl`/mach-вызовы доступны в песочнице.
- **Архитектура:** `SystemMetricsService` (protocol, выдаёт `AsyncStream<MetricsSnapshot>`), `MetricsViewModel` с ring-buffer, `MetricsPresetView`. Опрос — 1–2 Гц **только когда панель раскрыта**, 0.2 Гц для чипа, полная остановка при `occlusionState != .visible` и при сне.
- **Риски:** энергия (см. §7), «шумные» цифры; не показывать температуры без SMC.
- **Сложность/риск:** M / низкий-средний (энергия).
- **Конкуренты/дифференциатор:** Stats, iStat Menus, Sensei/CleanMyMac widgets. Дифференциатор: **нижняя панель + связка «файл → место на диске»** (сколько занимает папка, куда уходит место). [17][18][19]
- **Источники:** [17][18][19].

#### 4.1.6 Инбокс новых файлов (Downloads/Desktop watcher) — M, impact: высокий
- **Питч/проблема:** Downloads превращается в свалку; пользователь не помнит, что только что скачал, и боится удалять.
- **В панели:** collapsed — «4 новых файла»; expanded — лента за 24 часа/7 дней с превью, размером, типом; действия: «в папку», «в корзину», «открыть», «показать», «тег». Hover — Quick Look thumbnail.
- **API и разрешения:** `FSEvents` (наблюдение за папкой) или `DispatchSource` на vnode (только для одной папки); `NSMetadataQuery` для «за последние 24 часа»; `URLResourceValues.contentModificationDate`, `fileSize`, `typeIdentifier`. Папка выбирается пользователем → security-scoped bookmark, Full Disk Access не нужен.
- **Sandbox/App Store:** совместимо, если папка выбрана через `NSOpenPanel` (Downloads/Desktop доступны и так, но лучше явный выбор).
- **Архитектура:** `InboxWatcherService` (protocol) с `AsyncStream<InboxEvent>`, `InboxViewModel` (дедуп по `fileResourceIdentifier`, игнор `.download`/`.crdownload`), `InboxPresetView`. Переиспользовать bookmark-инфраструктуру FastFolder.
- **Риски зависаний:** сетевые тома и iCloud Drive (`isUbiquitousItem`, `ubiquitousItemDownloadingStatus`) — не читать содержимое, только метаданные; FSEvents-лаг и «шторм» событий при распаковке архива → debounce 0.5–1 с.
- **Сложность/риск:** M / низкий-средний.
- **Конкуренты/дифференциатор:** Hazel (правила, дорого/сложно), CleanMyMac (уборка), Finder «Загрузки». Дифференциатор: **glance + triage в один бросок**, без правил и автоматизации. [34]
- **Источники:** [34] + Apple File System Programming Guide / FSEvents.

### 4.2 Средние

#### 4.2.1 AI-drop: суммаризация, перевод, переименование (FoundationModels) — M, impact: высокий
- **Питч/проблема:** бросил PDF/текст/картинку — получил выжимку, перевод или аккуратное имя файла. Без облака, без подписки.
- **В панели:** collapsed — чип «AI готов» после обработки; expanded — карточка результата с диффом (старое/новое имя), кнопки «Применить», «Скопировать», «Ещё вариант»; drag&drop — основной вход.
- **API и разрешения:** `FoundationModels` (macOS 26+): `SystemLanguageModel.default.availability`, `LanguageModelSession`, `@Generable` для структурированного вывода, `Tool` для вызова файловых операций; image attachments — в 2026 API есть. Разрешений нет, но нужен Apple Intelligence и поддерживаемое устройство [35]. Fallback — Vision OCR + эвристики.
- **Sandbox/App Store:** совместимо; Private Cloud Compute требует отдельного entitlement и одобрения — **не** использовать в v1.
- **Архитектура:** `AIService` (protocol, `summarize`, `translate`, `suggestName`), `AIViewModel` с `state`, `AIDropCard`. Все вызовы — async, отмена по уходу с пресета. Гард: `availability != .available` → показывать «AI недоступен» и не ломать панель.
- **Риски:** модель может галлюцинировать в именах/датах → всегда показывать preview и требовать подтверждения; ограничение длины контекста → чанкинг; язык/локаль.
- **Сложность/риск:** M / средний (зависимость от железа и включённого Apple Intelligence).
- **Конкуренты/дифференциатор:** NotchNook (облачные агенты/терминал), Cove (on-device AI), Raycast AI. Дифференциатор: **локально + файловый drop + «применить к файлу»**, а не чат. [1][10][12][35]
- **Источники:** [1][10][12][35].

#### 4.2.2 Скриншот-регион → OCR/аннотация/шаринг — M, impact: средний
- **Питч/проблема:** «выдели область, распознай текст, отправь» — три приложения сейчас.
- **В панели:** collapsed — кнопка «⛶»; expanded — «Снять область» → оверлей выделения → карточка результата (текст + картинка), действия: копировать текст/картинку, OCR, AirDrop; hover — превью.
- **API и разрешения:** ScreenCaptureKit `SCScreenshotManager.captureImage(contentFilter:configuration:)` (macOS 14+) [36] — требует **Screen Recording TCC**, после выдачи нужен перезапуск приложения [37]; Vision OCR [31]; аннотации — `PencilKit`/Core Graphics.
- **Sandbox/App Store:** технически совместимо, но Screen Recording — «тяжёлое» разрешение и частые re-consent prompts; App Review смотрит строго.
- **Архитектура:** `ScreenCaptureService` (protocol), `ScreenshotViewModel`, `RegionSelectionOverlay` (отдельное borderless-окно). Обязательно проверять `CGPreflightScreenCaptureAccess()` и вести пользователя в System Settings.
- **Риски:** энергия (короткий захват — ок, постоянный стрим — нет), приватность (на экране могут быть секреты), «фиолетовый» индикатор.
- **Сложность/риск:** M / средний-высокий (permission).
- **Конкуренты/дифференциатор:** CleanShot X, системный скриншот, Dropover (текст). Дифференциатор: **скриншот сразу в полку и в OCR**, без сохранения на диск. [13][36][37]
- **Источники:** [13][31][36][37].

#### 4.2.3 Батарея и «железо» как glance — M, impact: средний
- **Питч/проблема:** здоровье батареи, циклы, температура, заряд AirPods/мыши — раз в месяц нужно, но вспоминаешь редко.
- **В панели:** collapsed — «87% · 1:42 до разряда»; expanded — циклы, health %, температура, кто ест энергию (топ-3 по `ProcessInfo`/`powermetrics` — нет, только публичное), заряд Bluetooth-устройств.
- **API и разрешения:** `IOPSCopyPowerSourcesInfo` + `IOPSGetPowerSourceDescription` (публично), IORegistry `AppleSmartBattery` для циклов/температуры (ключи недокументированы, но стабильны), Bluetooth — `system_profiler SPBluetoothDataType -json` как безопасный fallback (публичный CLI, без разрешений). CoreBluetooth требует `NSBluetoothAlwaysUsageDescription`.
- **Sandbox/App Store:** IORegistry-чтение обычно проходит, но ключи не гарантированы; CoreBluetooth в песочнице — с entitlement/usage string.
- **Архитектура:** `PowerService` (protocol), `BatteryViewModel`, `BatteryPresetView`; обновление по `NSWorkspace.didWakeNotification` + раз в 60 с.
- **Риски:** хрупкие ключи SMC/IORegistry между моделями Mac; не строить на этом критические решения.
- **Сложность/риск:** M / средний (хрупкость недокументированных ключей).
- **Конкуренты/дифференциатор:** AlDente, iStat, Stats, NotchNook (Battery). Дифференциатор: **«сколько осталось при текущей нагрузке» + заряд аксессуаров в одном чипе**. [18][24][17]
- **Источники:** [17][18][24].

#### 4.2.4 Clipboard → Shelf bridge + сниппеты — M, impact: низкий-средний
- **Питч/проблема:** скопировал ссылку/картинку — хочу «припарковать» её в полке или отправить в папку, не открывая приложение.
- **В панели:** collapsed — «＋ из буфера»; expanded — карточка последнего элемента (текст/URL/картинка) с действиями: в полку, в заметку, открыть, «сделать сниппет».
- **API и разрешения:** `NSPasteboard.general.changeCount` (polling), `NSPasteboardItem`, `NSPasteboard.accessBehavior` (macOS 26 — проверить) — узнать, разрешено ли чтение; `detectedPatterns(for:)` — определять тип **без** уведомления пользователя [38].
- **Sandbox/App Store:** совместимо, но в macOS 26 программативное чтение пастборда вызывает **системный запрос**; пользователь может запретить [39][40].
- **Архитектура:** `PasteboardService` (protocol) с `AsyncStream<PasteboardChange>`; не хранить историю — только «последний элемент», чтобы не конкурировать со Spotlight.
- **Риски:** приватность (пароли/коды), Apple может ужесточить; **не** делать полноценный менеджер истории.
- **Сложность/риск:** M / средний (privacy + платформенный тренд).
- **Конкуренты/дифференциатор:** Spotlight (macOS 26, ⌘4), Maccy, Paste, Raycast. Дифференциатор: **мост «буфер → файл/папка»**, а не история. [16][38][39][40][41]
- **Источники:** [16][38][39][40][41].

#### 4.2.5 Парковка окна / базовый тайлинг через Accessibility — M, impact: низкий-средний
- **Питч/проблема:** «бросить окно вниз/в угол» без хоткеев; при этом macOS 26 уже умеет базовый тайлинг.
- **В панели:** collapsed — ничего; expanded — «Парковка окон»: список окон текущего Space, drag окна в панель → пресет позиции (снизу/слева/справа/центр); hover — превью рамки.
- **API и разрешения:** Accessibility API: `AXIsProcessTrustedWithOptions`, `AXUIElementCreateApplication`, `kAXWindowsAttribute`, `AXPosition`/`AXSize`; список окон — `CGWindowListCopyWindowInfo` (bounds/owner без разрешений, **имена окон требуют Screen Recording**). Accessibility TCC — пользователь включает вручную.
- **Sandbox/App Store:** AX разрешён, но App Review задаёт вопросы; в песочнице работает (TCC отдельно от sandbox).
- **Архитектура:** `WindowService` (protocol), `WindowParkingViewModel`; `AXUIElementSetMessagingTimeout` обязательно (зависшее приложение не должно вешать панель).
- **Риски:** Stage Manager (окна «не на сцене» отсутствуют в AX-списке), full-screen приложения, приложения без AX-поддержки; высокий процент «не сработало».
- **Сложность/риск:** M / высокий (permission + хрупкость + конкуренция).
- **Конкуренты/дифференциатор:** Rectangle, Loop, Magnet, macOS 26 tiling. Дифференциатор: **drop-жест вниз**, а не хоткей. [21][22]
- **Источники:** [21][22].

#### 4.2.6 Быстрый захват: заметка/задача/напоминание — S/M, impact: средний
- **Питч/проблема:** мысль/задача появляется в момент, когда руки заняты; открывать Notes/Reminders долго.
- **В панели:** collapsed — «＋» и поле ввода по клику; expanded — 3 последних заметки, «в Reminders с датой», «в Notes»; drag&drop текста/файла — создать заметку с вложением.
- **API и разрешения:** `TextEditor` + локальное хранилище (SwiftData/файл), EventKit `EKReminder` + `requestFullAccessToReminders()` + `NSRemindersFullAccessUsageDescription`; App Intents для «Сохранить в Notes» (через Shortcuts) или AppleScript к Notes (Automation TCC).
- **Sandbox/App Store:** локальные заметки — да; Reminders — с usage string; AppleScript к Notes — `NSAppleEventsUsageDescription` + `com.apple.security.automation.apple-events`.
- **Архитектура:** `QuickCaptureService`, `QuickCaptureViewModel`, `ScratchpadView`; автосохранение с debounce.
- **Риски:** конфликт с Tot/Notes; ценность только если «всегда под рукой» — значит, чип в свёрнутом состоянии обязателен.
- **Сложность/риск:** S–M / низкий.
- **Конкуренты/дифференциатор:** Tot, NotchNook (notes/tasks), Raycast Notes. Дифференциатор: **заметка + файл в одном броске**. [1][28]
- **Источники:** [1][28].

### 4.3 Амбициозные

#### 4.3.1 Per-app громкость (Core Audio process taps) — L, impact: высокий
- **Питч/проблема:** «сделай тише браузер, но оставь музыку» — системно невозможно; SoundSource/Background Music решают, но это отдельные приложения.
- **В панели:** collapsed — иконка «микшер»; expanded — список активных аудио-приложений со слайдерами и mute; hover — индикатор уровня.
- **API и разрешения:** Core Audio taps: `CATapDescription` + `AudioHardwareCreateProcessTap` (macOS 14.2+), перечисление — `kAudioHardwarePropertyProcessObjectList`, маппинг PID — `kAudioHardwarePropertyTranslatePIDToProcessObject`; далее нужно микшировать в output (aggregate device / IOProc) [42][43]. Разрешение — **System Audio Recording** (`NSAudioCaptureUsageDescription` в Info.plist, TCC `kTCCServiceAudioCapture`), без «фиолетового» индикатора и без Screen Recording [44][45].
- **Sandbox/App Store:** технически возможно, но требует аудио-разрешения и сложной аудио-архитектуры; App Review — обоснование обязательно.
- **Архитектура:** `AudioMixerService` (protocol) + `AudioProcessStore` (`@Observable`, `apps: [AudioApp]`, `levels: [AudioObjectID: Float]`), `MixerViewModel`, `MixerPresetView`. Всё аудио — на отдельном actor/queue, UI — только снапшоты.
- **Риски:** задержка/дрейф, эхо, конфликт с Bluetooth-устройствами, «сломалось после апдейта»; энергия при постоянном tap.
- **Сложность/риск:** L / высокий.
- **Конкуренты/дифференциатор:** SoundSource, Background Music (open source), NotchNook/DynamicLake (только общая громкость). Дифференциатор: **микшер в нижней панели, в один hover**. [44][45]
- **Источники:** [42][43][44][45].

#### 4.3.2 Локальная передача на телефон/другой Mac (LocalSend-подобная) — L, impact: средний
- **Питч/проблема:** AirDrop капризен между платформами; «отправить файл на Android/Windows» — боль.
- **В панели:** collapsed — «Устройства рядом: 2»; expanded — список устройств, drag файла на устройство; прогресс; история.
- **API и разрешения:** `Network` (NWListener/NWBrowser, Bonjour), `URLSession` поверх TLS с самоподписанными ключами (`CryptoKit`), `NSLocalNetworkUsageDescription` (local network privacy), опционально `NWPathMonitor` для выбора интерфейса.
- **Sandbox/App Store:** sandbox + network client/server разрешены; local network prompt обязателен; App Review может спросить про шифрование/экспорт.
- **Архитектура:** `TransferService` (protocol), `DiscoveryService`, `TransferViewModel` с очередью и retry; вся сеть — вне MainActor.
- **Риски:** безопасность (сопряжение, подтверждение на приёмнике), NAT/файрвол, «почему не видит» — огромная поддержка.
- **Сложность/риск:** L / высокий.
- **Конкуренты/дифференциатор:** AirDrop, LocalSend, Dropover Cloud, NotchDrop Pro (local sharing). Дифференциатор: сомнительный — лучше **не** в первых версиях. [5][13]
- **Источники:** [5][13].

#### 4.3.3 Система плагинов/пресетов (расширяемость) — L, impact: высокий (долгосрочно)
- **Питч/проблема:** одна команда не покроет все сценарии; экосистема расширений — то, что сделало Raycast и DynamicLake.
- **В панели:** expanded — «магазин/установленные пресеты»; drag&drop конфигурации; collapsed — чипы установленных плагинов.
- **API и разрешения:** App Intents как «безопасные плагины» (Shortcuts-команды), либо собственный декларативный формат (JSON) + `NSXPCConnection` для изолированных расширений; `SMAppService` для хелперов.
- **Sandbox/App Store:** App Intents — самый безопасный путь; сторонние бинарные плагины — риск для нотаризации и безопасности.
- **Архитектура:** `PresetRegistry`, `PresetProvider` (protocol), динамическая регистрация в навигации; каждый пресет — свой Service+VM+View (уже соответствует вашей архитектуре).
- **Риски:** API-контракт придётся версионировать; поддержка сторонних плагинов съедает время.
- **Сложность/риск:** L / средний.
- **Конкуренты/дифференциатор:** DynamicLake (plugins/market), Raycast (extensions), Boring Notch (extension system в roadmap). Дифференциатор: **пресеты, а не команды** — визуальные, drop-ориентированные. [2][3][12]
- **Источники:** [2][3][12].

#### 4.3.4 Now Playing + тексты (осторожно) — M/L, impact: средний
- **Питч/проблема:** «что играет» и «какие слова» — самая частая нотч-фича; но публичного API нет.
- **В панели:** collapsed — чип с обложкой/названием; expanded — транспорт, прогресс, текст (синхронизированный).
- **API и разрешения:** `MPNowPlayingInfoCenter` — только **публикация** своего контента, не чтение чужого [46]. Чтение — MediaRemote (приватный), с macOS 15.4 прямой вызов не работает; MediaRemoteAdapter запускает `/usr/bin/perl` с bundle id `com.apple.*` [47]. AppleScript к Music/Spotify — Automation TCC, без обложек и реального времени.
- **Sandbox/App Store:** **несовместимо** с App Store (private framework + запуск системного интерпретатора); нотаризация возможна, но хрупко.
- **Архитектура:** `NowPlayingService` (protocol) с несколькими бэкендами (AppleScript fallback / adapter), `NowPlayingViewModel`.
- **Риски:** ломается на каждом минорном апдейте; юридически серая зона; тексты — внешние API (авторские права).
- **Сложность/риск:** M–L / очень высокий.
- **Конкуренты/дифференциатор:** NotchNook, Boring Notch, DynamicLake, LyricFever, Music Presence. Дифференциатор: слабый — все уже это делают. **Рекомендуется не делать** (см. §6). [46][47][3]
- **Источники:** [3][46][47].

| **2** | **«Дальше»: встреча + Join** (4.1.3) | Даёт причину держать панель включённой весь день (glance), а не только когда тащишь файл. Один permission, понятный пользователю. | Retention: панель становится «часами дня», а не утилитой. |
| **3** | **AI-drop (on-device)** (4.2.1) | Сильный маркетинговый дифференциатор при отсутствии серверов и подписок: приватность + «применить к файлу». | Воспринимаемая «современность»; апселл-потенциал (Pro). |
| **4** | **Инбокс новых файлов** (4.1.6) | Уникальная для нижней панели история: «что упало в Downloads» — это буквально «внизу экрана». Без разрешений (bookmark). | Возвраты каждое утро/после скачивания; связка с FastFolder. |
| **5 (бонус)** | **Keep Awake + мини-виталка** (4.1.4/4.1.5) | Дёшево (S), закрывает «утилитарные» ожидания и заполняет свёрнутое состояние чипами. | Быстрый «вау» без разрешений; удерживает от установки Amphetamine/Stats. |

### 5.2 Порядок и обоснование

1. **Сначала «полка + инбокс»** — обе работают на существующей файловой инфраструктуре (security-scoped bookmarks FastFolder), не требуют TCC и не ломают архитектуру. Это фундамент: полка становится «шиной», к которой потом подключаются OCR, AI, конвертация.
2. **Потом «Дальше»** — единственное «постоянное» значение в свёрнутом состоянии. Требует аккуратной работы с EventKit (denial → empty state) и с фоновыми обновлениями.
3. **Потом AI** — как надстройка над полкой: «бросил → получил». Если Apple Intelligence недоступен, фича просто скрывается, продукт остаётся целым.
4. **Виталка/Keep Awake** — параллельно, как «наполнение» для свёрнутого состояния, не как отдельная большая работа.

### 5.3 Чего избегать в первых версиях

- Не начинать с музыки (media) — риск и поддержка несоразмерны.
- Не начинать с window management — конкуренция с Rectangle/Loop и встроенным тайлингом macOS 26, высокий процент «не работает».
- Не начинать с per-app audio — самая сложная аудио-архитектура; делать только если есть человек с опытом Core Audio.

## 7. Технические предусловия и риски

### 7.1 TCC-матрица

| Разрешение | Что триггерит | Info.plist ключ | Нюансы |
|---|---|---|---|
| **Accessibility** | `AXIsProcessTrustedWithOptions`, `AXUIElement*` | — | Нельзя «запросить» программно — только открыть System Settings; изменения подхватываются не всегда без перезапуска; привязано к подписи/bundle id |
| **Screen Recording** | `SCShareableContent`, `SCStream`, `SCScreenshotManager`, имена окон в `CGWindowListCopyWindowInfo` | — | После выдачи нужен **перезапуск** приложения [37]; в 15+ периодические повторные подтверждения; «фиолетовый» индикатор |

### 7.2 Sandbox, подпись, нотаризация

- **Sandbox** (если когда-нибудь App Store): `com.apple.security.app-sandbox`, `com.apple.security.files.user-selected.read-write`, `com.apple.security.files.bookmarks.app-scope` (для 8 папок FastFolder), `com.apple.security.network.client`. Drag&drop из Finder даёт доступ к конкретным файлам; **путь, вставленный текстом, доступа не даёт**.
- **Direct distribution**: Developer ID + Hardened Runtime + `notarytool` + stapling. Любая загрузка приватных фреймворков (MediaRemote) — риск отказа/поломки при апдейте; не закладывать в ядро.
- **TCC привязан к подписи**: смена сертификата/команды → пользователь заново выдаёт Accessibility/Screen Recording. Это ещё причина не строить продукт на «тяжёлых» разрешениях.
- **Login item**: `SMAppService.mainApp.register()` (macOS 13+) — без хелперов; `status` для UI «включено/требует подтверждения» [48].
- **Обновления**: Sparkle 2 (подпись EdDSA) — стандарт для direct distribution.

### 7.3 Энергопотребление

- Правило: **энергия тратится только когда панель видима**. Останавливать таймеры при `window.occlusionState != .visible`, при `NSWorkspace.screensDidSleepNotification`, при `willSleepNotification`.
- Опрос: 1–2 Гц для раскрытой виталки, 0.2 Гц для чипа, 0 — когда свёрнуто и не наведён курсор. Использовать `DispatchSourceTimer` с `leeway` (10–20%) вместо `Timer`.
- Для фоновых задач — `NSBackgroundActivityScheduler` (система сама батчит), а не «свой цикл».
- Никаких постоянных `SCStream`; `SCScreenshotManager` — одноразово.
- Измерять: Instruments «Energy Log», `powermetrics --samplers tasks` (нужен root, только для замеров), `os_signpost` вокруг тяжёлых операций.

### 7.4 Multi-display и clamshell

- Панель привязана к **встроенному** дисплею: определять через `CGDisplayIsBuiltin(displayID)` или `NSScreen.localizedName`; нотч — через `NSScreen.safeAreaInsets.top > 0` (плюс `auxiliaryTopLeftArea`/`auxiliaryTopRightArea`).
- **Clamshell / только внешний монитор**: встроенного экрана нет → панель нужно либо скрыть, либо перенести на главный экран (настройка «разрешить на внешних дисплеях», как у DynamicLake [2]).
- **Dock**: позиционировать по `visibleFrame`, а не `frame`; учитывать auto-hide Dock и «Dock справа/слева».
- **Stage Manager**: окна «не на сцене» не видны в AX; панель может оказаться за краем рабочего стола.
- **Full-screen**: `collectionBehavior` должен включать `.fullScreenAuxiliary` и `.canJoinAllSpaces`, иначе панель исчезает в полноэкранных приложениях.
- **Сон/пробуждение**: пересоздавать окно/пересчитывать позицию по `NSWorkspace.didWakeNotification` и `NSApplication.didChangeScreenParametersNotification`.

### 7.5 macOS 26 (Tahoe): что важно

| Изменение | Влияние на Panel |
|---|---|
| **Liquid Glass** | Стоит adopt: SwiftUI `.glassEffect(_:in:)` / `GlassEffectContainer` (macOS 26+) [49]; но на светлых обоях «Clear»-стекло плохо читается — нужен fallback на непрозрачный фон и настройка контраста |
| **Spotlight: история буфера (⌘4), Actions, нет Launchpad** | Убивает смысл clipboard-менеджера; зато появляется привычка «всё через Spotlight» → панель должна давать то, чего в Spotlight нет: файлы и drag&drop [41] *(проверить)* |
| **Запрос доступа к пастборду** | `NSPasteboard.accessBehavior`, `detectedPatterns(for:)` без уведомления; программное чтение — только после согласия [38][39][40] *(проверить)* |
| **Shortcuts Automations** | Триггеры по времени/папке/сообщению → можно сделать «панель как исполнитель»: App Intents + автоматизация «файл в папке → показать в панели» [41] |
